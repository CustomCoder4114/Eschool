Flow 1. Find - the parent searches for the child (name, email or student ID) and selects the right student. 2. Method - Link code : the student generates a one-time code (e.g. "ESK-7H4-Q9M") in their account settings. Code is verified against the selected student and the link is created instantly. Email : the student receives an approval request and must accept it before the link becomes active. 3. Verify - enter the code (code method) or confirm where the request will be sent (email method). 4. Access - relationship + what the parent can see. 5. Confirm - review and consent. Backend endpoints this page expects (JSON): GET /api/parent/links -> { links: [{ id, student_name, student_email_masked, student_avatar_url, grade, school, relationship, status ("active"|"pending"|"declined"|"expired"), method ("code"|"email"), linked_at, requested_at, expires_at, permissions: { grades, schedule, attendance, resources, notifications } }] } POST /api/parent/links/find { query } -> { students: [{ id, name, email_masked, avatar_url, grade, school }] } (empty list when nothing matches) POST /api/parent/links/lookup { method: "code", code, student_id } -> { student: { id, name, email_masked, avatar_url, grade, school } } (404 / 410 on bad, mismatched or expired code) POST /api/parent/links/email-request { student_id } -> { request: { id, status: "pending", expires_at } } Emails the student a Yes/No question. (409 already linked/pending, 429 sent too recently) GET /api/parent/links/email-request/ -> { request: { id, status } } status: "pending" | "approved" | "declined" | "expired" (polled every 4 seconds while waiting) DELETE /api/parent/links/email-request/ -> cancels a pending request POST /api/parent/links { method: "code"|"email", code?, request_id?, student_id, relationship, permissions: {...}, consent: true } -> { link: {...} } (email method: request_id must be an APPROVED request for this parent + student; the link is created active straight away) PATCH /api/parent/links//permissions { permissions: {...} } POST /api/parent/links//resend -> { link: {...} } DELETE /api/parent/links/ -> unlink (active) or cancel (pending) #}
